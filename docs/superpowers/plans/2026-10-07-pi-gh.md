# pi-gh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native) or superpowers:subagent-driven-development according to the user's chosen execution method. Steps use checkbox syntax.
**Goal:** gh-issueflowを独立したPi拡張として移管し、承認済みの公開候補をnpmへ公開する。
**Architecture:** ホスト非依存コア、承認service、Piの7 toolsとTUI adapterを分離する。標準ghと元の安全境界を維持し、旧CLIは変更しない。
**Tech Stack:** TypeScript、Node.js >=22.19.0、Pi 1.0.4、既存yaml dependency、node:test、隔離PTY/loopback。
**Spec:** docs/superpowers/specs/2026-10-07-pi-gh-design.md

## Global Constraints
- repo ~/Documents/Github/pi-gh、GitHub KendrickMalar/pi-gh、npm @papillon6814/pi-gh@0.1.1、MIT、公開binなし。
- 元gh-issueflow SHA 99acc816e653a4b945d62a2d8fbfca745bcdcf5dを読み取り基準とし、旧コード・認証・履歴を変更しない。
- Pi 1.0.4、Node >=22.19.0。ホスト提供Pi/TypeBox/TUIはpeer "*"、実体をruntime dependencyへ含めない。
- feat/bootstrap-pi-ghでGit初期化・最初の文書commitを行い、初期branchをmainへ改名後、git worktree addでfeat/initial-issueflowを作る。main直commit・mainで製品コード編集はしない。
- 既存docsの保存は完了。実装・Git・依存導入はユーザーの計画承認と実行方式選択後。
- TUIのみ外部変更を許可。承認フラグ、approvedDigest、UI bypassをモデル入力に追加しない。
- 非対話、取消、session/branch/runtime変更、入力/remote変更は未送信。起動後の取消/異常はunknown、自動再試行なし。
- GH_HOST=github.com、shellなし、60秒・各stdio1MiB・cleanup100ms、POSIX所有process groupを終了。
- input1MiB、JSON/YAML depth32、remote一覧100ページ/合計1MiB、decoded秘密情報検査を維持。
- 公開/導入・CI/CD変更・実GitHubテスト・認証操作は計画承認に含めない。各対象と影響を別確認。
- 開発と試験は今回の絶対worktreeパスとsynthetic HOMEで行い、無関係なauto-worktreeを使わない。

## Review Focus
1. UI確認中の別session/reload、または確認後remote再検査中の切替からwriteが発生しない。Task2/3。
2. 小さい端末・日本語・resize・terminal control文字で対象が隠れたり確認ボタンが誤作動しない。Task3。
3. 初期signal abort、write開始前/開始後の取消、親exit後に残るpipeを区別して期限内に終了する。Task1/2。
4. コピー後のtemplate/policy path、インストール先の空白・cwd違いでも同じ検査対象とdigestを使う。Task1/4。
5. decoded秘密情報・object key・remote metadata・例外・details/structuredContentを経由して生の候補を表示/公開しない。Task2/4。

## インターフェース
- 既存core exportsは保持し、importsをsrc/core内へ合わせる。CLI/packageテストのみ新契約へ置換する。coreテストを削減して合格扱いにしない。
- GhOptionsにsignal?: AbortSignal、beforeStart?: () => booleanを追加。runGhの戻り型は既存GhResultを保持し、起動前拒否はnot-started、起動後取消はunknown。
- Operation = gh_issue_validate | gh_issue_preview | gh_issue_submit | gh_labels_validate | gh_labels_preview | gh_labels_apply | gh_issue_form。
- IssueArgs = {draftPath:string; template?:'parent'|'task'; templatePath?:string}、LabelsArgs = {changePath:string}、FormArgs = {template?:'parent'|'task'; templatePath?:string}。default taskはserviceで解決し、schemaへ自動補完しない。
- ApprovalView = {operation:Operation; text:string; digest:string}。textはマスク済み全文。
- OperationContext = {cwd:string; packageRoot:string; interactive:boolean; signal:AbortSignal; stamp:string; isCurrent:()=>boolean; confirm:(view:ApprovalView)=>Promise<boolean>}。
- runOperation(operation:Operation,args:IssueArgs|LabelsArgs|FormArgs,context:OperationContext):Promise<OperationResult>をsrc/service.tsからexport。
- OperationResult = {status:string; data?:unknown; problems?:ValidationProblem[]; message?:string}。公開statusはvalidated/preview/generated/created/applied/noop/rejected/not-started/unknown。
- RuntimeScopeはextensions/runtime-scope.ts。current stamp生成、isCurrent(stamp)、invalidate()、runExclusive<T>(fn:()=>Promise<T>):Promise<T>を提供。invalidateで保有AbortControllerをabortし、古いqueueは確認UIを開かない。
- showApproval(view:ApprovalView,context:{signal:AbortSignal;isCurrent:()=>boolean},ui:ExtensionContext['ui']):Promise<boolean>をextensions/approval-ui.tsからexport。各呼出しで新しいcomponentを作る。
